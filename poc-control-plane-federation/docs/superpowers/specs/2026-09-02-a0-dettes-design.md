# A0 — les deux dettes

## Ce que la critique a changé

| Constat (lentille) | Décision |
|---|---|
| **Bloquant (forge)** : la garde « jamais un commentaire du compte de service sur une PR seulement NOMMÉE par le payload » était posée sur le statut, pas sur le **verdict** — `provision-plan.sh` commente `PR_NUMBER` tel quel (`:105-107`), sans relire la forge | La relecture de la forge entre dans **`provision-plan.sh`, AVANT le clone** (lib partagée) : refus nommé `FORGE_NON_CONFIRMEE`, rc 1, aucun commentaire ; les faits relus sont écrits dans un fichier que le statut consomme (une seule vérité, pas de TOCTOU) |
| **Bloquant (parité)** : `test-palier-retention` ㉑septies rougit dès que le littéral `choices: ['dev', 'rec', 'int', 'homol']` disparaît | Réancrage sur la **dérivation** (mutation `env_chain_nonprod` → `env_chain`, détecteur structurel), vue code Groovy pour le Jenkinsfile |
| Important ×4 : le `post{always}{node{checkout scm}}` inconditionnel alloue un exécuteur et clone pour **chaque** PR du dépôt (onboard/*, promote/*…) — l'argument même de `agent none` | Gardes bon marché en Groovy **AVANT** `node` (`PR_BRANCH` ~ `provision/*`, `PR_NUMBER` numérique), `try/catch` + `timeout` autour du nœud ; même correctif sur `provision-apply` |
| Important ×3 : la contre-épreuve « branche inexistante ⇒ build rouge » est fausse (`git checkout` non gardé, diff vide ⇒ `IGNORE` exit 0 ⇒ vert) | `checkout` fatal (`BRANCHE_INTROUVABLE`) ; contre-épreuve réécrite : **branche réelle de la PR A + `PR_NUMBER` de la PR B** ⇒ `FORGE_NON_CONFIRMEE`, ni verdict ni statut sur B, A intacte |
| Important ×3 : le corps SUCCESS « le verdict est dans le commentaire provision-plan » ment quand le plan a été **ignoré** (aucun manifeste : aucun commentaire) | `PLAN_VERDICT=ok\|fail\|ignore\|refus` (+ raison) dans les faits ; corps distincts ; en SUCCESS+ok le statut n'est posé **que s'il existe déjà** (efface un rouge périmé) — pas de troisième commentaire redondant |
| Important ×4 : « plus aucune liste littérale nulle part » est faux — `ci/Jenkinsfile.publish-api:24` garde `['dev','rec','int','prod']` et **c'est elle qui gagne** (fusion par nom) sur `publish-api-deploy` posé par le même template | L'énoncé se réduit à `Jenkinsfile.selfservice` + `setup-selfservice-job.sh` ; l'exception `publish-api` est **nommée** par une épreuve (chaîne des APIs, hors périmètre, liste du producteur avec terminus : décision de périmètre à trancher là-bas) |
| Important ×2 : le fait 2 (properties() préserve les triggers) était mesuré sur des propriétés venues du XML, pas sur `options{}`/`triggers{}` déclaratifs | **Mesuré** (fait 6, ci-dessous) |
| Important (ops) : `setup-selfservice-job.sh` attend l'amorçage 90 s alors que le préflight gateway peut durer 300 s ; sans `--print`, l'épreuve « XML dérivé à la pose » est vacante | Knob `BOOTSTRAP_WAIT` (défaut 360 s), distinction « encore en cours » / échec ; mode `--print` (XML sur stdout, zéro réseau) |
| Mineur ×3 : fait 5 (EnvVars.resolve) non traité pour l'aval — mot de passe portant `$` altéré avant Vault | **Mesuré** (fait 7) : vrai. `withEnv([params…])` autour des trois stages de l'aval, mot de passe compris |
| Mineur : `gitea-pr-comment.sh` sans timeout ni pagination | `timeout=30`, pagination `limit=50&page=N`, knob `COMMENT_ONLY_IF_EXISTS` |
| Mineur : D1.b « aucune PR avant le succès » inexact au rejeu (PR préexistante `EXIST`, `ERR` après `POST /pulls`) | Documenté tel quel dans le Jenkinsfile, jamais prétendu par l'épreuve |

## Faits mesurés (jobs jetables a0-spike2 / a0-spike3, 2026-09-02, supprimés)

6. **Un XML qui porte déjà une `ParametersDefinitionProperty` + `properties([parameters])` ⇒ DEUX propriétés** (7 noms relus, dont doublons) et le job **casse** (`buildWithParameters` ⇒ HTTP 500, le webhook enfile un build qui ne démarre pas). Le step ne retire jamais une propriété qu'il n'a pas posée — même de sa propre classe. Avec un XML **sans** paramètre : une seule propriété ; `options{disableConcurrentBuilds}` et `triggers{GenericTrigger}` **déclaratifs** sont préservés à l'amorçage (`POST /build` 201), au `buildWithParameters` et au build par webhook (`triggered:true`, la variable GWT s'ajoute aux paramètres liés). Corollaire de rollout : **la conversion d'un job à formulaire passe par une RE-POSE** (POST config.xml efface paramètres ET trackers) puis un amorçage ; un simple `git push` du Jenkinsfile sur un job dont le XML garde ses paramètres le casse.
7. **`EnvVars.resolve()` frappe aussi les paramètres `password`** : `A$$B${JENKINS_HOME}C` arrive au shell en 21 octets (`A$B/var/jenkins_homeC`) par le canal natif, en 20 octets intacts par `withEnv(["P=${params.P}"])` (sha256 égal à l'attendu). Un mot de passe annuaire contenant `$$` ou `${` est donc altéré aujourd'hui avant Vault (lockout AD au deuxième essai).
8. `params.X` d'un paramètre `password` est lisible en String dans le sandbox et ré-injectable par `withEnv` ; une valeur vide en `withEnv` retire la variable (`EnvVars.override`), ce que `${VAULT_USER_PASSWORD:-}` côté lib absorbe (PLAN-only inchangé).

## Décisions

### D1 — `provision-plan` : la forge relue AVANT le verdict, le statut nourri par les faits

- **`scripts/lib/gitea-pr-confirm.sh`** (à sourcer) : `gitea_pr_confirm <n> <head_ref_attendu> [base_attendue]` — `GET /repos/<repo>/pulls/<n>` (python, token par env, `timeout=30`) ; rc 0 et lignes `GITEA_STATE=open`, `GITEA_HEAD_REF`, `GITEA_HEAD_SHA`, `GITEA_BASE_REF` sur stdout **seulement si** `state == open`, `head.ref == attendu`, `head.ref` ~ `^provision/`, `base.ref == base attendue` ; sinon rc 1 et `FORGE_NON_CONFIRMEE : <raison>` sur stderr (404, 5xx, timeout, non-objet, champs absents, `\n` dans une valeur, mismatch, fermée/mergée). Le numéro est validé `^[0-9]+$` avant de composer l'URL.
- **`scripts/provision-plan.sh`** : après la garde `provision/*`, **avant** le clone : `gitea_pr_confirm "$PR_NUMBER" "$PR_BRANCH" "$GIT_BASE"` ⇒ refus rc 1 sans commentaire ; le clone checkoute **`GITEA_HEAD_SHA`** relu (lie le numéro au contenu : une branche `provision/<app>-<env>` réutilisée après merge ne fait pas commenter une PR mergée), `|| REFUS: BRANCHE_INTROUVABLE` rc 1 ; fichier de faits `PLAN_FACTS` (si posé) écrit sur **chaque** sortie : `GITEA_HEAD_REF`, `GITEA_HEAD_SHA`, `PLAN_VERDICT=refus|ignore|ok|fail`, `PLAN_REASON`. Changement de parité assumé et écrit : un `checkout` raté ne rend plus vert. L'appel enchaîné de `provision-request.sh` [5/5] (PR ouverte, branche = head) reste vert.
- **`scripts/provision-plan-status.sh`** : lit `PLAN_FACTS` ; **faits absents** (le stage n'a pas tourné : agent injoignable, clone raté) ⇒ relecture de la forge par la **même** lib ; non confirmé ⇒ `exit 0` sans commentaire. Corps (sans accents) : `SUCCESS`+`ok` ⇒ upsert **seulement si** un statut existe déjà (`COMMENT_ONLY_IF_EXISTS=1`) ; `SUCCESS`+`ignore` ⇒ « demande IGNOREE (<raison>) : aucun verdict, rien a valider » ; `ABORTED` ⇒ « abandonne, aucun verdict, rejouer le webhook » ; `FAILURE`+`fail` ⇒ « verdict NEGATIF, voir provision-plan » ; `FAILURE`+`refus` ⇒ « refus avant le verdict : <raison> » ; `FAILURE` sans faits ⇒ « echec avant le plan (agent ?), voir le log » ; repli `BUILD_REF` = `JOB_NAME #BUILD_NUMBER` quand `BUILD_URL` est vide. Marqueur `<!-- provision-plan-build -->`.
- **`scripts/lib/gitea-pr-comment.sh`** : `urlopen(timeout=30)` ; pagination `?limit=50&page=N` jusqu'à page vide ; knob `COMMENT_ONLY_IF_EXISTS=1` (marqueur absent ⇒ `COMMENT_SKIPPED`, rc 0).
- **`ci/Jenkinsfile.provision-plan`** : `sh 'set +x; PLAN_FACTS="$WORKSPACE/.plan.facts" bash scripts/provision-plan.sh'` ; `post{always}` de **stage** qui charge les faits dans `env.` (`GITEA_HEAD_REF`, `PLAN_VERDICT`, `PLAN_REASON`) ; `post{always}` de **pipeline** : `script { if (!(PR_BRANCH ~ provision/*) || !(PR_NUMBER ~ [0-9]+)) { echo; return } ; try { timeout(2 min) { node { checkout scm ; withCredentials ; withEnv([BUILD_RESULT]) { dir { sh 'set +x; bash scripts/provision-plan-status.sh || echo AVERTISSEMENT' } } } } } catch (e) { echo AVERTISSEMENT } }`.
- **`ci/Jenkinsfile.provision-apply`** : même garde Groovy avant le `node` du `post{always}`, `try/catch` + `timeout` (le gate forge `GITEA_HEAD_REF` du `sh` reste).
- **`provisioning-request`** : pas de `post{always}` — documenté avec ses nuances (la PR naît en [4/5] ; [5/5] non fatal ; au rejeu une PR peut préexister et un échec avant [4/5] la laisse muette ; `ERR`/réponse illisible après `POST /pulls`) ; épreuve statique de ces faits.

### D2 — `selfservice-app-deploy` : formulaire posé par le Jenkinsfile, XML sans paramètre

- **`ci/Jenkinsfile.selfservice`** : le bloc `parameters{}` disparaît ; premier stage « Formulaire — paliers dérivés de la chaîne » sous `dir('poc-control-plane-federation')` : `bash -c '. scripts/lib/env-chain.sh && env_chain_nonprod' > "$WORKSPACE/.a0-envs"`, `readFile`, chaque palier validé `^[a-z0-9]+$` (`FORMULAIRE_INVALIDE`, définitions précédentes conservées), puis `properties([parameters([ … 8 … choice(name: 'ENVIRONMENT', choices: envs) … ])])` — descriptions verbatim ; `options{}`/`triggers{}` restent déclaratifs (fait 6). Les trois stages suivants (Référence, Plan, Apply) passent sous `withEnv(["MANIFEST=${params.MANIFEST}", "MERGE_SHA=…", "ENVIRONMENT=…", "ADMIN_VIA=…", "DEBUG=…", "VAULT_USER=…", "USER_VAULT_JWT=…"])`, l'Apply ajoutant `"VAULT_USER_PASSWORD=${params.VAULT_USER_PASSWORD}"` (fait 7). Ordre Formulaire < Référence < Plan < Apply, ancré.
- **`scripts/setup-selfservice-job.sh`** : knob `XML_PARAMS` (`auto` : `no` quand `SCRIPT_PATH` est `Jenkinsfile.selfservice` — le formulaire est posé par le Jenkinsfile, fait 6 —, `yes` sinon : `publish-api-deploy` garde son bloc déclaratif et ses paramètres XML comme ceinture SECURITY-170) ; en mode `yes`, la `<choices>` d'`ENVIRONMENT` est **dérivée à la pose** de `env_chain_nonprod` (validée, échappée par ElementTree — plus de littéral) ; `--print` (XML rendu sur stdout, zéro réseau) ; amorçage `POST /build` (sans paramètre XML) ou `buildWithParameters` ; `BOOTSTRAP_WAIT` (défaut 360 s) avec « encore en cours » distingué d'un échec ; **relecture après amorçage** : exactement UNE `ParametersDefinitionProperty` (fait 6, sinon message « job cassé par un push sans re-pose : re-poser ») et, en mode `no`, `ENVIRONMENT == env_chain_nonprod`. Résiduel nommé : ce poseur n'a ni auth Jenkins ni portail (parité avec `setup-provision-jobs.sh` à faire le jour du rollout client).
- Hors périmètre, nommé : `ci/Jenkinsfile.publish-api:24` (liste du producteur avec terminus), `ci/Jenkinsfile.api-promote-request:44`.

### D3 — Épreuves

- `scripts/test-a0-wiring.sh` §9 (D1) : lib confirm contre le stub Gitea d'A2 (open/closed/mismatch/404/500/non-objet/`\n`) ; `provision-plan.sh` refuse **avant** tout clone (stub : `FORGE_NON_CONFIRMEE`, zéro POST/PATCH, faits `refus`) ; statut : les 6 corps, `ONLY_IF_EXISTS`, faits absents ⇒ relecture, non confirmé ⇒ aucun appel ; câblage : facts dans le `sh`, `post` de stage, garde Groovy **avant** `node` (numéros de ligne), `try`/`timeout`, marqueur distinct ; `provision-apply` : garde avant `node` ; `provisioning-request` : les faits documentés (`[4/5]` < `[5/5]`, `PLAN_INLINE=fail` non fatal). §10 (D2) : pas de `parameters {` déclaratif, `properties([` avec les 8 noms, `choices: envs`, validation des paliers, `withEnv` des 8 (mot de passe dans l'Apply seul), ordre des stages, `setup-selfservice-job.sh --print` avec `STOA_ENV_CHAIN_FILE` à 6 paliers (ElementTree : 0 paramètre en mode `no`, `ENVIRONMENT` dérivé en mode `yes`, terminus absent), mutation `env_chain_nonprod`→`env_chain` ⇒ terminus présent, `gwt_mirror_diff(--print, Jenkinsfile.selfservice)` ⇒ `MIROIR_OK`.
- `test-provision-apply-wiring.sh` : garde avant `node` dans le post ; §9 `L_PROPS < L_REQ`. `test-palier-retention.sh` : ㉑sexies (vue code Groovy), ㉑septies réancré (mutation de la dérivation), ㉑nonies nomme l'exception `publish-api`. `test-pr-comment.sh` : `ONLY_IF_EXISTS`, pagination.
- **Live** : `test-a0-live.sh` étendu — SUCCESS+ok ⇒ **aucun** statut (pas de troisième commentaire) ; contre-épreuve : webhook `stoa-provision-plan` forgé avec `PR_BRANCH` = branche réelle de la PR A et `PR_NUMBER` = PR B ⇒ `provision-plan` FAILURE `FORGE_NON_CONFIRMEE`, comptes de commentaires de A et B inchangés ; branche inexistante ⇒ FAILURE aussi (forge : la PR nommée n'a pas cette tête). `test-selfservice-form-live.sh` (nouveau, court) : re-pose (`wm-keepalive.pause` posé pendant), amorçage, config relue (1 propriété, 8 paramètres, `ENVIRONMENT == env_chain_nonprod` depuis gitea main, trigger `stoa-selfservice-plan` + `disableConcurrentBuilds` présents), webhook PLAN `triggered:true` ; puis **`test-provision-apply-a2-live.sh` rejoué** (60/60 attendu) : l'aval appliqué par `build job:` sous `properties()`, mot de passe réel d'alice via `withEnv`.

## Rollout

`git push gitea HEAD:main` → **re-poser** (jamais push seul, fait 6) : `bash scripts/setup-selfservice-job.sh` (XML sans paramètre + amorçage + relecture), puis `JOBS="provision-plan provision-apply" bash scripts/setup-provision-jobs.sh` (le Jenkinsfile de plan a changé : pas de re-pose nécessaire pour lui — from SCM — mais le miroir des triggers est inchangé ; provision-apply idem). Aucun geste sur `provisioning-request`.
